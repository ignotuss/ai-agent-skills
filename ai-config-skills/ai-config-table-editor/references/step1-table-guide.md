# 第 1 步：按需求修改表格

## 第 0 步（技能流程）：改表前输出方案卡并等待确认

- 检索知识页与当前数据，确认目标表与改动方式；存在歧义或跨表影响时必须先把“方案卡”给用户确认，确认后再改。
- 必须等待确认：跨多张表、映射歧义、知识库未覆盖的新依赖、删除/覆盖已有数据、特殊字段、涉及额外权限的改动。
- 免确认：需求精确无歧义，或用户明确“直接改”。

### 方案卡模板

```text
需求：
目标表：
改动明细：
  - 表/行/列：旧值 -> 新值
影响面：
  - 关联表/规则：
  - 是否同步 Apollo：是/否（默认只提交不发布）
  - steam/敏感字段：未涉及 / 仅存在性校验 /（确认后）修改
歧义点与推荐：
后续动作：改表 -> 校验 -> 导出 Conf*.json -> 同步 Apollo
```

## 执行前

1. 明确需求涉及的配置表，先读 [table-knowledge/index.md](table-knowledge/index.md) 找到对应知识页。
2. 用知识页里的依赖规则判断影响面：改了这张表会不会影响别的表（被引用/引用谁）。
3. **项目隔离**：按项目进入 `card/`、`super-chameleon/` 等子目录；同名表在不同项目语义可能不同，严禁套用其它项目规则。
4. 若知识库未覆盖：先只读分析表格与相关表，把疑似依赖列给用户确认，确认后再动手或补录到对应项目目录。

## 修改源表

- 源表目录按项目约定配置（本仓库使用占位符 `$CONFIG_XLSX_DIR`，例如某项目为 `Configs/Card`）。
- 文件被 Excel 打开时（存在 `~$` 锁文件）不能安全地外部写入：会报文件占用，或覆盖掉用户未保存的修改。必须先让用户保存并关闭 Excel，或经 Excel 自身会话修改。
- 修改后读回校验：确认只改了目标行/列，未破坏表头与结构。

## 修改后

- 跑项目中的一致性校验，全部通过再进入第 2 步导出。
- 发现新依赖或新不一致时，记录下来并让用户确认后再固化规则。
- 修改未涉及任何已固化依赖规则时，明确提醒“未被依赖覆盖，建议手动检查”。
